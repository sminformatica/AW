    Parte 1: Ejemplo Práctico Guiado (Inspección de Cuentas y Plugins de Autenticación)

    Sigue los siguientes pasos en la consola para comprobar cómo MariaDB gestiona la seguridad y los métodos de autenticación de cada cuenta de usuario.

    Paso 1: Consultar la tabla de usuarios del sistema

    1. Abre tu terminal (Ctrl + Alt + T).
    2. Accede a la consola de MariaDB como superusuario: 
      sudo mariadb -u root
    3. Ejecuta la siguiente consulta para examinar los usuarios, sus hosts permitidos y sus plugins de autenticación: 
      SELECT User, Host, plugin FROM mysql.user;
    4. Observa la diferencia entre el usuario root (que habitualmente usa unix_socket) y el usuario admin_smx creado en la sesión anterior (que usa mysql_native_password o autenticación estándar por clave).

    Paso 2: Comprobación del socket Unix vs TCP

    1. Sal de la consola de MariaDB: 
      EXIT;
    2. Realiza una conexión forzando el protocolo TCP sobre la dirección IP de bucle local: 
      mariadb -h 127.0.0.1 -u admin_smx -p
    3. Introduce la contraseña Smx2026!Pass.
    4. Una vez dentro, ejecuta el comando de estado: 
      STATUS;
    5. Localiza la línea Connection: y comprueba que indica 127.0.0.1 via TCP/IP.
    6. Sal de la consola (EXIT;).

    Parte 2: Práctica Autónoma de Diagnóstico y Consolidación

    Realiza las siguientes comprobaciones de forma individual para validar tu destreza en la resolución de incidencias comunes de la capa de datos.

    Tareas a Realizar

    1. Inspección del Archivo de Configuración de Red:
    2. Abre en modo lectura el archivo de configuración del servidor MariaDB: 
      cat /etc/mysql/mariadb.conf.d/50-server.cnf | grep bind-address

    3. Anota en tu informe qué dirección IP tiene asignada la directiva bind-address y qué implicación técnica tiene para la seguridad del equipo.

    4. Simulación de Incidencia: Desactivación del Alias de phpMyAdmin en Apache:

    5. Deshabilita temporalmente el archivo de configuración de phpMyAdmin en el servidor web Apache ejecutando: 
      sudo a2disconf phpmyadmin
sudo systemctl reload apache2
    6. Abre el navegador y accede a http://localhost/phpmyadmin. Comprueba qué código de error devuelve Apache (404 Not Found).
    7. Restaura la configuración volviendo a habilitar el módulo: 
      sudo a2enconf phpmyadmin
sudo systemctl reload apache2

    8. Recarga la página en el navegador y comprueba que vuelve a cargar la pantalla de login.

    9. Verificación de Registros de Error (Logs):

    10. Visualiza las últimas 10 líneas del archivo de registro de MariaDB para comprobar que no existen alertas de corrupción o errores de inicio: 
      sudo tail -n 10 /var/log/mysql/error.log

    Comprobación de Comandos

    Recuerda que a2enconf (Apache2 Enable Configuration) y a2disconf (Apache2 Disable Configuration) son las utilidades oficiales en Debian/Ubuntu para activar o desactivar módulos auxiliares sin borrar archivos del sistema.
