    Práctica 2.6: Copias de Seguridad, Volcados SQL y Restauración de Bases de Datos

    Ficha de la Sesión

    • Módulo: Aplicaciones Web (2º SMX)
    • Unidad de Trabajo: UD 2 — Bases de Datos para la Web
    • Sesión: Sesión 2.6 (4 horas - Sesión Integrada Semanal)
    • Entorno de trabajo: LliureX 21 / Ubuntu Desktop 24.04 LTS
    • Resultados de Aprendizaje: RA2 (Criterios c, d, e)

    Parte 1: Ejemplo Práctico Guiado (Exportación, Desastre y Restauración)

    Sigue atentamente estos pasos guiados para realizar una copia de seguridad de la base de datos tienda_fuster, provocar deliberadamente un desastre simulado (borrado de datos) y restaurar el servicio por dos vías distintas.

    Paso 1: Exportación Completa con phpMyAdmin

    1. Accede a http://localhost/phpmyadmin con el usuario admin_smx.
    2. En el panel izquierdo, haz clic sobre la base de datos tienda_fuster.
    3. Haz clic en la pestaña superior Exportar.
    4. Selecciona el método de exportación Personalizado:
      • Comprueba que están seleccionadas todas las tablas (categorias, clientes, productos).
      • En la sección Opciones de creación de objetos, marca la casilla: [x] Añadir sentencia DROP TABLE / VIEW / PROCEDURE / DATABASE.
      • En Compresión, selecciona Ninguno (o Comprimido en zip).
    5. Haz clic en el botón Exportar al final de la página. Se descargará el archivo tienda_fuster.sql.

    Paso 2: Inspección del Archivo de Volcado

    1. Abre tu editor de texto o visualiza las primeras líneas del archivo descargado desde la terminal: 
      head -n 35 ~/Descargas/tienda_fuster.sql
    2. Identifica los bloques de comentarios informativos, las directivas de codificación utf8mb4 y las sentencias CREATE TABLE e INSERT INTO.

    Paso 3: Simulación de Desastre (Pérdida de Datos)

    1. Vuelve a phpMyAdmin y selecciona la base de datos tienda_fuster.
    2. Haz clic en la pestaña Operaciones.
    3. En la zona inferior enmarcada en rojo, haz clic en Eliminar la base de datos (DROP) y confirma la acción.
    4. Comprueba que tienda_fuster ha desaparecido del árbol de bases de datos de la izquierda.

    Paso 4: Restauración Gráfica desde phpMyAdmin

    1. Ve a la pestaña principal Bases de datos y crea de nuevo la base de datos vacía llamada tienda_fuster con cotejamiento utf8mb4_unicode_ci.
    2. Selecciona la recién creada tienda_fuster en el menú izquierdo.
    3. Haz clic en la pestaña superior Importar.
    4. Haz clic en Seleccionar archivo y elige tienda_fuster.sql desde tu carpeta de Descargas.
    5. Baja hasta el final y pulsa Continuar.
    6. Verifica que aparece el mensaje verde de confirmación: La importación se ha ejecutado con éxito.

    Parte 2: Práctica Autónoma Evaluativa

    Realiza las siguientes tareas de forma individual para validar tu competencia profesional en planes de contingencia y automatización de respaldos desde terminal.

    Escenario de Trabajo

    Como técnico de sistemas del IES Joan Fuster, debes implementar un procedimiento de copia de seguridad mediante consola para la base de datos de producción tienda_fuster, simular una corrupción parcial de datos en la tabla de productos y realizar una recuperación en frío mediante la herramienta mariadb-dump.

    Tareas a Realizar

    1. Exportación por Terminal mediante mariadb-dump:
    2. Crea una carpeta de respaldos en tu directorio personal: 
      mkdir -p ~/backups_smx
    3. Ejecuta el comando mariadb-dump utilizando el usuario usr_tienda para exportar la base de datos completa a un archivo con fecha: 
      mariadb-dump -u usr_tienda -p tienda_fuster > ~/backups_smx/tienda_fuster_completa.sql
    4. Introduce la contraseña del usuario (Tienda2026!Pass).

    5. Comprueba que el archivo se ha creado y tiene un tamaño superior a cero (ls -lh ~/backups_smx/).

    6. Exportación Modular Exclusiva de una Sola Tabla:

      • Genera una copia de seguridad que contenga únicamente la tabla productos: 
        mariadb-dump -u usr_tienda -p tienda_fuster productos > ~/backups_smx/solo_productos.sql

    7. Simulación de Incidencia: Vaciado Accidental de la Tabla productos:

      • Accede a la consola de MariaDB o a phpMyAdmin y ejecuta la orden para vaciar todos los registros de la tabla: 
        USE tienda_fuster;
TRUNCATE TABLE productos;
      • Comprueba mediante una consulta SELECT * FROM productos; que la tabla ha quedado completamente vacía (0 filas).

    8. Restauración por Terminal:

      • Restaura la tabla de productos a partir de la copia modular generada en el paso 2: 
        mariadb -u usr_tienda -p tienda_fuster < ~/backups_smx/solo_productos.sql
      • Vuelve a consultar la tabla en MariaDB o phpMyAdmin y verifica que los 18 productos originales están íntegros y accesibles.

    9. Automatización con un Script Bash de Respaldo:

      • Crea en tu carpeta personal el script ~/backups_smx/backup_diario.sh: 
        #!/bin/bash
FECHA=$(date +%Y%m%d_%H%M)
DESTINO="/home/$USER/backups_smx"
mariadb-dump -u usr_tienda -pTienda2026!Pass tienda_fuster > "$DESTINO/backup_auto_$FECHA.sql"
echo "Copia completada con exito: backup_auto_$FECHA.sql"
      • Asigna permisos de ejecución al script (chmod +x ~/backups_smx/backup_diario.sh).
      • Ejecuta el script y comprueba que genera automáticamente el archivo con la marca temporal.

    Buenas Prácticas de Backup

    En los scripts automatizados se concatena el parámetro -p con la contraseña sin espacios (ejemplo: -pMiClave). Esto permite la ejecución desatendida sin solicitar interacción al usuario.

    Genera un documento PDF denominado UD02_S2.6_Apellido_Nombre.pdf con las siguientes evidencias:

    1. Captura 1: Salida del comando head -n 25 ~/backups_smx/tienda_fuster_completa.sql mostrando las directivas SQL generadas.
    2. Captura 2: Consulta SELECT COUNT(*) FROM productos; mostrando 0 registros tras ejecutar el TRUNCATE TABLE.
    3. Captura 3: Ejecución del comando de restauración en la terminal de Linux sin errores.
    4. Captura 4: Consulta SELECT * FROM productos; en phpMyAdmin o consola demostrando que los datos se han recuperado íntegramente.
    5. Captura 5: Salida del comando ls -la ~/backups_smx/ donde se aprecie el script backup_diario.sh con permisos de ejecución y los archivos .sql generados.
