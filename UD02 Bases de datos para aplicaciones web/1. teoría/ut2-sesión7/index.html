    2.7: Copias de Seguridad, Volcados SQL y Restauración de Bases de Datos

    En esta sesión integrada vas a aprender a planificar y ejecutar estrategias de respaldo en la capa de datos. Analizarás la estructura interna de un archivo de volcado .sql, comprenderás la diferencia entre sentencias DDL y DML, y dominarás los procedimientos de exportación e importación tanto desde la interfaz gráfica de phpMyAdmin como desde la consola de Linux.

    2.7.1 La Importancia de las Copias de Seguridad en Aplicaciones Web

    En cualquier servicio web en producción (tiendas online, gestores de contenidos, plataformas educativas), la base de datos es el elemento más crítico: contiene usuarios, pedidos, artículos y configuraciones.

    Un fallo de disco, un error humano al borrar una tabla, un fallo en una actualización de un plugin o un ciberataque pueden provocar la pérdida total del servicio si no se cuenta con un plan de respaldo adecuado.

    • Copia de seguridad en caliente (Hot Backup): Se realiza con el motor de base de datos en funcionamiento continuo sin interrumpir el servicio web a los usuarios.
    • Volcado lógico (Logical Dump): Exportación de la base de datos en un archivo de texto plano con extensión .sql que contiene las instrucciones exactas necesarias para recrear toda la estructura y volver a insertar los datos.

    2.7.2 Estructura de un Archivo .sql: Sentencias DDL frente a DML

    Cuando abres un archivo de copia de seguridad .sql en un editor de texto, observas que el volcado está dividido en dos tipos de instrucciones del estándar SQL:

    Tipo de Sentencia Descripción Ejemplos
    DDL (Data Definition Language) Definen la estructura y arquitectura de las tablas. CREATE DATABASE, CREATE TABLE, DROP TABLE, ALTER TABLE
    DML (Data Manipulation Language) Contienen los datos e información que residen en las filas. INSERT INTO, UPDATE, DELETE 
    -- Ejemplo de bloque DDL (Crea la tabla si no existe)
DROP TABLE IF EXISTS `categorias`;
CREATE TABLE `categorias` (
  `id` int(11) NOT NULL AUTO_INCREMENT,
  `nombre` varchar(100) NOT NULL,
  PRIMARY KEY (`id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- Ejemplo de bloque DML (Inserta los datos de respaldo)
INSERT INTO `categorias` (`id`, `nombre`) VALUES
(1, 'Redes y Cableado'),
(2, 'Dispositivos de Red');

    2.7.3 Métodos de Exportación en phpMyAdmin

    phpMyAdmin ofrece dos modalidades de exportación:

    1. Método Rápido: Genera un volcado completo de todas las tablas de la base de datos seleccionada con opciones estándar (recomendado para respaldos habituales).
    2. Método Personalizado: Permite un control granular sobre el proceso:
      • Seleccionar tablas específicas (por ejemplo, exportar solo la tabla productos sin exportar la tabla clientes).
      • Elegir si exportar solo la estructura (DDL), solo los datos (DML) o ambos.
      • Añadir sentencias de seguridad como DROP TABLE / VIEW / PROCEDURE para sobrescribir esquemas existentes durante la restauración.
      • Seleccionar compresión al vuelo (.zip o .gzip) para bases de datos de gran tamaño.

    2.7.4 Herramientas de Respaldo por Consola: mariadb-dump / mysqldump

    En tareas de administración de sistemas y automatización de tareas programadas (cron jobs), el respaldo no se hace manualmente mediante un navegador web, sino utilizando la herramienta de línea de comandos:

    • Exportar (Copia de seguridad): 
      mariadb-dump -u usuario -p nombre_bd > copia_seguridad.sql
    • Importar (Restauración de datos): 
      mariadb -u usuario -p nombre_bd < copia_seguridad.sql

    Punto Crítico en la Restauración

    Antes de importar un volcado SQL mediante la línea de comandos (< copia.sql), la base de datos de destino debe existir previamente en el motor MariaDB, a menos que el propio archivo .sql contenga explícitamente la sentencia CREATE DATABASE.
