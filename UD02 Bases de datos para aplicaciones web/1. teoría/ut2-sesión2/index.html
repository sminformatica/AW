    2.2: Arquitectura de Red de MariaDB, Autenticación y Resolución de Incidencias

    En esta sesión de consolidación vas a asentar los conceptos clave sobre la comunicación interna del motor MariaDB, la diferencia entre sockets Unix y conexiones TCP/IP, los métodos de autenticación de usuarios y las técnicas de diagnóstico ante errores habituales en phpMyAdmin.

    2.2 Arquitectura de Red y Mecanismos de Conexión en MariaDB

    Para que una aplicación web pueda consultar una base de datos, el cliente (PHP o phpMyAdmin) debe comunicarse con el servidor MariaDB. En sistemas Linux existen dos métodos para establecer este canal de comunicación:

    1. Sockets Unix (localhost):

      • Se utiliza cuando el cliente web y el motor de base de datos residen en la misma máquina física.
      • La comunicación se realiza mediante un archivo especial del sistema de archivos (habitualmente /run/mysqld/mysqld.sock).
      • No viaja por la pila de protocolos de red TCP/IP, lo que reduce la latencia y mejora el rendimiento.

    2. Conexiones de Red TCP/IP (127.0.0.1 o IP remota):

      • La comunicación se realiza a través de la interfaz de red en el puerto 3306 TCP.
      • Permite separar la aplicación web en un servidor y la base de datos en otro servidor dedicado dentro de la red local.

    2.3 Métodos de Autenticación de Usuarios

    En MariaDB, la identidad de un usuario no se define únicamente por su nombre, sino por el par Usuario @ Host de origen:

    Cuenta = 'usuario'@'host'

    • 'admin_smx'@'localhost': El usuario solo puede conectar desde la propia máquina local.
    • 'admin_smx'@'192.168.1.%': El usuario puede conectar desde cualquier equipo de la subred 192.168.1.0/24.
    • 'admin_smx'@'%': El usuario puede conectar desde cualquier dirección IP (no recomendado por seguridad).

    Existen además distintos plugins de autenticación:

    • auth_socket / unix_socket: Valida el acceso comprobando si el usuario que ejecuta el comando en Linux coincide con el usuario de la BD (utilizado por defecto por root en la terminal).
    • mysql_native_password / caching_sha2_password: Valida el acceso mediante comprobación de contraseña tradicional (necesario para accesos web vía phpMyAdmin o aplicaciones PHP).

    2.4 Diagnóstico y Resolución de Incidencias Comunes

    Al trabajar con phpMyAdmin y servicios web, te enfrentarás a tres errores típicos:

    Error / Síntoma Causa técnica Procedimiento de corrección
    Error 404 en /phpmyadmin Apache no tiene cargado el archivo de configuración de phpMyAdmin. Ejecutar sudo ln -s /etc/phpmyadmin/apache.conf /etc/apache2/conf-available/phpmyadmin.conf, habilitarlo con sudo a2enconf phpmyadmin y reiniciar Apache.
    Access denied for user Contraseña incorrecta o usuario configurado con plugin auth_socket intentando entrar por web. Crear un usuario específico con contraseña asignada (IDENTIFIED BY '...') y otorgar permisos.
    Connection refused (3306) El demonio mariadb.service está detenido o la directiva bind-address bloquea la conexión. Verificar estado con sudo systemctl status mariadb e iniciar el servicio si está inactivo.

    Riesgo de Seguridad: Directiva bind-address

    El archivo de configuración /etc/mysql/mariadb.conf.d/50-server.cnf contiene por defecto la directiva bind-address = 127.0.0.1. Esto restringe la escucha exclusivamente a la máquina local, impidiendo ataques directos desde la red exterior al puerto 3306. Nunca cambies esta directiva a 0.0.0.0 a menos que sea estrictamente necesario y cuentes con un cortafuegos activo.
