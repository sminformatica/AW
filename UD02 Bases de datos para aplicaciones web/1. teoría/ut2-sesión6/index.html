    2.6: Gestión Granular de Usuarios, Privilegios y Seguridad en MariaDB (Teoría)

    En esta sesión de taller de 3 horas vas a estudiar en profundidad la capa de autenticación y autorización en los sistemas gestores de bases de datos. Aprenderás a crear cuentas de usuario independientes, a restringir el acceso según el host de origen y a aplicar el principio de menor privilegio otorgando permisos granulares sobre bases de datos concretas.

    Referentes de Evaluación y Concreción Curricular

    • Curso Académico: 2024-2025
    • Resultados de Aprendizaje (RA) Referentes:

      • CE 2.e: Se han asignado privilegios granulares aplicando el principio de menor privilegio a nivel de servidor, base de datos y objetos.

    2.6.1 Autenticación vs Autorización en Bases de Datos

    En la seguridad de cualquier servidor de bases de datos intervienen dos fases consecutivas:

    1. Autenticación (¿Quién eres?): El motor comprueba si el par formado por el nombre de usuario y el host de origen ('usuario'@'host') coincide con una cuenta registrada y valida su contraseña o mecanismo de autenticación.
    2. Autorización (¿Qué tienes permitido hacer?): Una vez autenticado, el motor consulta las tablas internas de privilegios para determinar qué acciones exactas puede ejecutar ese usuario (lectura, inserción, modificación de esquemas, borrado) y sobre qué elementos específicos (todo el servidor, una base de datos, una tabla o una columna).

    2.6.2 El Principio de Menor Privilegio aplicado a la Web

    El Principio de Menor Privilegio (Principle of Least Privilege) es una directiva básica de seguridad informática: cada componente o usuario de un sistema debe tener acceso únicamente a la información y recursos estrictamente necesarios para cumplir su función.

    En el desarrollo y administración web:

    • Mala práctica: Conectar WordPress, PrestaShop o una aplicación a medida utilizando el usuario root o un usuario con permisos globales (*.*). Si la aplicación sufre una vulnerabilidad de inyección SQL (SQLi), el atacante podría acceder a todas las bases de datos del servidor, alterar tablas del sistema o ejecutar comandos.
    • Buena práctica: Crear una base de datos específica (por ejemplo tienda_fuster) y un usuario exclusivo (por ejemplo usr_tienda) cuyos permisos se limiten única y exclusivamente a esa base de datos.

    2.6.3 Niveles y Tipos de Privilegios en MariaDB

    Los privilegios en MariaDB se agrupan según el tipo de operación:

    Categoría Privilegios Principales Función / Acción permitida
    Manipulación de Datos (DML) SELECT, INSERT, UPDATE, DELETE Leer registros, añadir filas, modificar campos y borrar datos existentes en las tablas.
    Estructura y Esquema (DDL) CREATE, ALTER, DROP, INDEX Crear nuevas tablas, modificar tipos de columnas, borrar tablas enteras o crear índices.
    Administración Global SUPER, GRANT OPTION, RELOAD, SHUTDOWN Cambiar configuraciones del motor, otorgar permisos a otros usuarios y reiniciar el servicio.

    Peligro: El Privilegio GRANT OPTION

    Nunca asignes el privilegio GRANT OPTION a los usuarios destinados a aplicaciones web. Esta directiva permite que un usuario otorgue a otros sus mismos permisos, lo que facilitaría a un atacante elevar privilegios en el motor.
