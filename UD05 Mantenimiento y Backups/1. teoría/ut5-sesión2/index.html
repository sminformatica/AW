    5.2: Empaquetado, Clonación y Migración de Sitios WordPress con Duplicator

    En esta sesión vas a estudiar los procedimientos técnicos de migración y clonación de aplicaciones web basadas en WordPress. Analizarás el problema de la serialización de datos en las bases de datos relacionales, comprenderás cómo empaquetar una instalación completa y aprenderás a desplegarla en un nuevo entorno utilizando la herramienta profesional Duplicator.

    5.2.1 El Desafío de la Migración en WordPress: Rutas Absolutas y Serialización

    Copiar manualmente los archivos de WordPress y volcar su base de datos no es suficiente para trasladar un sitio a otro servidor o directorio. WordPress almacena la dirección URL del sitio y las rutas del disco duro dentro de múltiples registros de la base de datos MariaDB (como siteurl y home en la tabla wp_options).

    • El problema de la serialización en PHP: Muchos plugins y temas guardan arrays u objetos estructurados utilizando la función serialize() de PHP. Una cadena serializada incluye la longitud exacta de cada texto (por ejemplo s:21:"http://localhost/blog";). Si realizas un simple "Buscar y Reemplazar" en un editor de texto o en phpMyAdmin sustituyendo esa URL por otra de longitud distinta, los conteos de bytes quedan rotos, la cadena serializada se invalida y los widgets, menús o maquetaciones de Elementor se corrompen de inmediato.
    • Solución técnica: El proceso de migración debe utilizar herramientas capaces de deserializar los datos en memoria, reemplazar las URLs y rutas físicas antiguas por las nuevas, y volver a serializar respetando las longitudes exactas de los datos.

    5.2.2 Los Dos Componentes del Paquete Duplicator

    A diferencia de las herramientas de copia estándar, Duplicator no requiere que WordPress esté previamente instalado en el servidor de destino. El proceso se basa en dos archivos indispensables:

    1. El Archivo Comprimido ([nombre_paquete]_archive.zip): Contiene una instantánea completa del sistema de archivos (wp-admin, wp-includes, wp-content, archivos raíz) junto con un volcado SQL de la base de datos exportado en un formato estructurado.
    2. El Script Instalador (installer.php): Un archivo independiente programado en PHP ligero que contiene el motor de descompresión, el asistente visual de instalación, el conector directo a MariaDB y el algoritmo de sustitución de URLs serializadas.

    5.2.3 Fases de un Proceso de Migración Profesional

    Todo traslado o clonación de un entorno web debe estructurarse en cuatro fases ordenadas:

    1. Fase Previa (Auditoría y Purga): Vaciar papeleras de entradas, purgar tablas de logs temporales, desactivar plugins de caché y comprobar que el archivo .zip no superará los límites de memoria de PHP.
    2. Fase de Empaquetado: Generación del paquete desde el plugin y descarga de installer.php y el archivo comprimido.
    3. Fase de Despliegue: Creación de una base de datos limpia en el nuevo servidor, copia de los dos archivos a la raíz web del destino y ejecución del script installer.php desde el navegador.
    4. Fase Posterior (Aseguramiento y Limpieza): Eliminación inmediata del script installer.php y del archivo de volcado para evitar brechas de seguridad que permitan reinstalar el sitio a atacantes externos.

    Riesgo Crítico de Seguridad: Archivos Huérfanos

    Dejar el archivo installer.php en el servidor web una vez finalizada la migración es una de las vulnerabilidades más explotadas en WordPress. Permite a cualquier usuario malintencionado sobreescribir la base de datos y tomar el control total del servidor. Asegúrate siempre de que el instalador borre sus archivos temporales.
