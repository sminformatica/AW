    Parte 1: Ejemplo Práctico Guiado (Monitorización con tail -f y Activación de WP_DEBUG)

    Sigue atentamente los siguientes pasos para monitorizar el servidor web en tiempo real desde la consola de Linux y activar el registro interno de incidencias de WordPress.

    Paso 1: Monitorización en Vivo de los Registros de Apache

    1. Abre un terminal (Ctrl + Alt + T).
    2. Ejecuta el comando tail con el parámetro -f (follow) para seguir en directo las peticiones entrantes: 
      sudo tail -f /var/log/apache2/access.log
    3. Abre tu navegador y navega por el sitio http://localhost/portal_produccion/.
    4. Observa cómo cada clic genera líneas en la consola con códigos de respuesta 200 OK, 304 Not Modified o 404 Not Found.
    5. Pulsa Ctrl + C para detener la monitorización.
    6. Abre en seguimiento el registro de errores: 
      sudo tail -f /var/log/apache2/error.log

    Paso 2: Habilitación de la Depuración en wp-config.php

    1. Abre en el editor de consola el archivo de configuración del sitio: 
      sudo nano /var/www/html/portal_produccion/wp-config.php
    2. Localiza la directiva define('WP_DEBUG', false); y reemplázala por el siguiente bloque de directivas de diagnóstico: 
      // Habilitar modo de depuracion
define('WP_DEBUG', true);

// Guardar avisos y errores en /wp-content/debug.log
define('WP_DEBUG_LOG', true);

// Impedir que los errores se muestren publicamente en la pantalla del usuario
define('WP_DEBUG_DISPLAY', false);
@ini_set('display_errors', 0);
    3. Guarda los cambios (Ctrl + O, Enter) y sal (Ctrl + X).

    Paso 3: Simulación de Error y Verificación del Archivo debug.log

    1. Fuerza una llamada a una función inexistente editando temporalmente el archivo functions.php del tema activo: 
      echo "<?php funcion_inexistente_prueba(); ?>" | sudo tee -a /var/www/html/portal_produccion/wp-content/themes/astra/functions.php
    2. Recarga la portada del sitio web en el navegador.
    3. Observa que el navegador muestra un mensaje técnico o error genérico sin exponer detalles sensibles.
    4. Consulta el archivo de registro generado por WordPress: 
      sudo cat /var/www/html/portal_produccion/wp-content/debug.log
    5. Comprueba que el archivo detalla el error: PHP Fatal error: Uncaught Error: Call to undefined function funcion_inexistente_prueba().
    6. Corrige el archivo eliminando la línea añadida y comprueba que la web vuelve a cargar correctamente.

    Parte 2: Práctica Autónoma Evaluativa

    Realiza la creación de un entorno de Staging con el plugin WP Staging, simula un fallo de actualización y recupera el sistema de forma individual.

    Escenario de Trabajo

    El departamento técnico del IES Joan Fuster va a aplicar una actualización mayor en plugins críticos de la tienda. Tienes prohibido realizar cambios directamente en el sitio en vivo. Debes clonar la web a un entorno aislado de pruebas, simular la rotura de un plugin esencial y resolver el incidente mediante la consola del sistema operativo.

    Tareas a Realizar

    1. Instalación de la Herramienta de Entornos de Pruebas:

      • En el panel de portal_produccion, ve a Plugins > Añadir nuevo plugin.
      • Busca: WP Staging – Backup Duplicator & Migration.
      • Instala y activa el plugin.

    2. Creación del Entorno Aislado (Staging Environment):

      • Ve a WP Staging > Staging Sites.
      • Haz clic en Create New Staging Site.
      • Asigna un nombre al entorno: pruebas-fuster.
      • Comprueba que el plugin selecciona todas las tablas de la base de datos (con un nuevo prefijo) y copia los archivos a una subcarpeta: /var/www/html/portal_produccion/pruebas-fuster/.
      • Haz clic en Start Cloning y espera a que concluya el proceso.

    3. Acceso y Auditoría del Entorno de Staging:

      • Abre una nueva pestaña y accede al entorno clonado: 
        http://localhost/portal_produccion/pruebas-fuster/wp-admin
      • Observa la barra superior con fondo naranja de advertencia (STAGING SITE).
      • Inicia sesión con tus credenciales de administrador.
      • Comprueba que la portada, las páginas y la tienda funcionan en esta ruta independiente sin alterar el sitio original.

    4. Simulación de Avería Crítica por Actualización:

      • En el entorno de Staging, ve a Plugins > Añadir nuevo plugin e instala un plugin secundario cualquiera.
      • Simula una actualización corrupta renombrando de forma errónea archivos internos o introduciendo un error de sintaxis PHP dentro de su archivo principal.
      • Comprueba que al intentar acceder a la web en Staging se produce un error crítico y el panel web queda bloqueado.

    5. Resolución de Emergencia por Terminal (CLI):

      • Abre la terminal de Linux.
      • Navega hasta la carpeta de plugins del entorno de pruebas: 
        cd /var/www/html/portal_produccion/pruebas-fuster/wp-content/plugins/
ls -la
      • Desactiva el plugin causante del fallo renombrando su directorio: 
        sudo mv nombre-del-plugin nombre-del-plugin_roto
      • Recarga la página en el navegador y verifica que WordPress arranca de nuevo indicando que el plugin ha sido desactivado automáticamente al no encontrar sus archivos.

    6. Auditoría de Consultas en MariaDB:

      • Accede a la consola de MariaDB y lista las tablas creadas por WP Staging: 
        sudo mariadb -u usr_fuster_prod -p bd_fuster_prod
      • Ejecuta SHOW TABLES; y localiza las tablas duplicadas para comprobar cómo se aíslan los datos entre el sitio en producción y el entorno de pruebas.

    Diferencia de Permisos en Entornos de Staging

    Al crearse la carpeta pruebas-fuster, asegúrate mediante ls -ld de que el propietario sigue siendo www-data:www-data para que Apache pueda procesar las actualizaciones sin solicitar credenciales FTP.

    2. Captura 2: Contenido del archivo /var/www/html/portal_produccion/wp-content/debug.log mostrando el error fatal simulado con fecha y pila de llamadas.
    3. Captura 3: Asistente de WP Staging mostrando la finalización exitosa del clonado hacia la subcarpeta pruebas-fuster.
    4. Captura 4: Navegador web en http://localhost/portal_produccion/pruebas-fuster/ con la barra superior de Staging activa.
