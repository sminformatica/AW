    Parte 1: Ejemplo Práctico Guiado (Bastionado Manual de Archivos y Permisos)

    Sigue atentamente los siguientes pasos en tu portal portal_produccion para asegurar los archivos clave del sistema a nivel de Linux y Apache.

    Paso 1: Bloqueo de Acceso a wp-config.php y xmlrpc.php en .htaccess

    1. Abre tu terminal (Ctrl + Alt + T).
    2. Edita el archivo .htaccess del sitio migrado: 
      sudo nano /var/www/html/portal_produccion/.htaccess
    3. Añade al principio del archivo las siguientes reglas de protección para denegar el acceso a archivos sensibles: 
      # Proteger wp-config.php de accesos HTTP
<Files wp-config.php>
Require all denied
</Files>

# Bloquear xmlrpc.php contra ataques de fuerza bruta
<Files xmlrpc.php>
Require all denied
</Files>

# Desactivar el listado de directorios
Options -Indexes
    4. Guarda los cambios (Ctrl + O, Enter) y sal (Ctrl + X).

    Paso 2: Verificación del Bloqueo desde el Navegador

    1. Abre el navegador web y accede a: 
      http://localhost/portal_produccion/wp-config.php
    2. Comprueba que el servidor Apache responde con un error 403 Forbidden (Acceso Denegado).
    3. Repite la prueba accediendo a: 
      http://localhost/portal_produccion/xmlrpc.php
    4. Verifica que también devuelve un error 403 Forbidden.

    Paso 3: Restricción de Permisos POSIX en Linux

    Ajusta los permisos del archivo de configuración para que solo el propietario pueda leerlo:

    sudo chmod 640 /var/www/html/portal_produccion/wp-config.php
sudo chown www-data:www-data /var/www/html/portal_produccion/wp-config.php

    Comprueba los permisos con ls -l /var/www/html/portal_produccion/wp-config.php y observa la máscara -rw-r-----.

    Paso 4: Desactivación del Editor de Archivos Interno

    1. Edita el archivo wp-config.php: 
      sudo nano /var/www/html/portal_produccion/wp-config.php
    2. Justo antes de la línea /* That's all, stop editing! Happy publishing. */, añade la siguiente directiva: 
      define('DISALLOW_FILE_EDIT', true);
    3. Guarda el archivo y accede a tu panel de administración en http://localhost/portal_produccion/wp-admin.
    4. Ve a Apariencia y Plugins: verifica que las opciones de Editor de archivos de temas y Editor de archivos de plugins han desaparecido por completo de los menús.

    Parte 2: Práctica Autónoma Evaluativa

    Realiza la instalación, optimización del cortafuegos y simulación de bloqueos de seguridad de forma individual.

    Escenario de Trabajo

    El departamento de sistemas del IES Joan Fuster te encarga proteger el portal corporativo contra ataques dirigidos. Debes instalar un cortafuegos WAF con Wordfence, optimizar su integración con el servidor web a nivel de PHP, configurar directivas de bloqueo ante intentos fallidos de inicio de sesión y simular un ataque de fuerza bruta para comprobar la respuesta del sistema.

    Tareas a Realizar

    1. Instalación y Activación de Wordfence Security:

      • En el panel de WordPress (portal_produccion), ve a Plugins > Añadir nuevo plugin.
      • Busca: Wordfence Security – Firewall, Malware Scan, and Login Security.
      • Instala y activa el plugin.
      • Introduce un correo para alertas de seguridad y selecciona la clave gratuita de licencia comunitaria (Get a Free License).

    2. Optimización del Cortafuegos (Nivel Extendido):

      • En el menú lateral, ve a Wordfence > Firewall.
      • Haz clic en el botón superior Manage Firewall y luego en Optimize the Wordfence Firewall.
      • El asistente detectará el servidor web (Apache + módulo PHP) y creará la directiva auto_prepend_file en el archivo .user.ini o .htaccess.
      • Descarga la copia de seguridad de .htaccess que solicita el asistente y haz clic en Continue.
      • Verifica que el estado del cortafuegos pasa de modo básico a Extended Protection.

    3. Configuración de Protección contra Fuerza Bruta (Brute Force Protection):

      • Dentro de Wordfence > Firewall > Manage Firewall, desplázate a la sección Brute Force Protection:
        • Lock out after how many login failures: Configura 3 intentos.
        • Lock out after how many forgot password attempts: Configura 3 intentos.
        • Count failures over what time period: 5 minutes.
        • Amount of time a user is locked out: 30 minutes.
        • Immediately lock out invalid usernames: Añade los nombres admin, administrador, root.
      • Haz clic en Save Changes en la esquina superior derecha.

    4. Simulación de Ataque de Fuerza Bruta:

      • Abre una ventana en modo incógnito/privado del navegador.
      • Accede a http://localhost/portal_produccion/wp-login.php.
      • Intenta iniciar sesión utilizando el nombre de usuario prohibido admin con cualquier contraseña inventada.
      • Comprueba que Wordfence bloquea inmediatamente el acceso mostrando una pantalla roja de advertencia con el mensaje de bloqueo temporal de IP (Your access to this site has been temporarily limited by the site owner).

    5. Auditoría de Intentos Bloqueados en el Panel:

      • Vuelve a tu navegador principal (donde tienes abierta la sesión de administrador).
      • Ve a Wordfence > Tools > Live Traffic.
      • Filtra por Blocked o Logins y localiza el registro del intento fallido:
        • Identifica la dirección IP de origen (127.0.0.1 o IP de red local).
        • Comprueba el motivo del bloqueo registrado por el cortafuegos.

    Desbloqueo de Emergencia

    Si te bloqueas accidentalmente a ti mismo durante las pruebas, puedes desbloquear tu IP accediendo al panel desde otra interfaz o editando temporalmente la base de datos MariaDB (tabla wp_wfblocks7).
