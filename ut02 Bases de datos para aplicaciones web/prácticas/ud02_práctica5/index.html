    Práctica 2.5: Gestión Granular de Usuarios, Privilegios y Seguridad en MariaDB

    Ficha de la Sesión

    • Módulo: Aplicaciones Web (2º SMX)
    • Unidad de Trabajo: UD 2 — Bases de Datos para la Web
    • Sesión: Sesión 2.5 (3 horas - Taller de Laboratorio)
    • Entorno de trabajo: LliureX 21 / Ubuntu Desktop 24.04 LTS
    • Resultados de Aprendizaje: RA2 (Criterios b, c, d)

    Parte 1: Ejemplo Práctico Guiado (Creación de Usuarios y Asignación de Privilegios)

    Sigue atentamente los siguientes pasos en phpMyAdmin para crear un usuario dedicado para la base de datos tienda_fuster y verificar el aislamiento de seguridad.

    Paso 1: Acceso con cuenta de administración

    1. Abre tu navegador y accede a http://localhost/phpmyadmin.
    2. Inicia sesión con la cuenta de administración creada previamente: admin_smx (contraseña Smx2026!Pass).

    Paso 2: Creación de la cuenta de usuario restringida

    1. En el menú superior principal, haz clic en Cuentas de usuarios.
    2. Haz clic en el enlace Agregar cuenta de usuario.
    3. Rellena los datos de inicio de sesión:
      • Nombre de usuario: usr_tienda
      • Nombre de host: Selecciona Local (aparecerá localhost).
      • Contraseña: Tienda2026!Pass
      • Volver a escribir: Tienda2026!Pass
    4. En el apartado Base de datos para la cuenta de usuario, marca la casilla:
      • [x] Otorgar todos los privilegios para la base de datos con el mismo nombre y / o tienda_fuster (o déjala sin marcar para asignarlos manualmente en el siguiente paso).
    5. En el bloque Privilegios globales, asegúrate de que todas las casillas permanecen desmarcadas.
    6. Haz clic en Continuar al final de la página.

    Paso 3: Asignación granular de privilegios sobre tienda_fuster

    1. Vuelve a la pestaña Cuentas de usuarios y localiza la fila de usr_tienda@localhost.
    2. Haz clic en Editar privilegios.
    3. Haz clic en la pestaña superior Base de datos (aparecerá un selector de bases de datos).
    4. Selecciona tienda_fuster en el listado y pulsa Continuar.
    5. En la pantalla de privilegios específicos para tienda_fuster:
    6. En Datos, marca: SELECT, INSERT, UPDATE, DELETE.
    7. En Estructura, marca: CREATE, ALTER, INDEX, DROP.
    8. En Administración, deja todo desmarcado.
    9. Haz clic en Continuar.

    Paso 4: Comprobación del Aislamiento de Seguridad

    1. Cierra sesión en phpMyAdmin haciendo clic en el icono de salida (puerta) del panel izquierdo.
    2. Inicia sesión con el nuevo usuario:
    3. Usuario: usr_tienda
    4. Contraseña: Tienda2026!Pass
    5. Observa el panel de navegación izquierdo:
    6. Verifica que únicamente se muestra la base de datos tienda_fuster (y information_schema por requerimiento del sistema).
    7. Comprueba que las demás bases de datos (mysql, phpmyadmin, bd_taller_smx) están completamente ocultas para este usuario.

    Parte 2: Práctica Autónoma Evaluativa

    Realiza las siguientes tareas de forma individual para validar tu destreza en la gestión de perfiles de usuario y comprobación de permisos mediante scripts PHP y la consola de comandos.

    Escenario de Trabajo

    El IES Joan Fuster va a desplegar un portal de noticias interno y requiere crear una base de datos independiente (bd_noticias_fuster) junto a dos cuentas de usuario con diferentes niveles de responsabilidad:

    1. Un usuario para la aplicación web (app_noticias) con permisos sobre datos y estructura de esa BD.
    2. Un usuario de solo lectura para auditoría (auditor_smx) que solo pueda consultar datos sin modificar nada.

    Tareas a Realizar

    1. Creación de la Base de Datos:

    2. Crea en phpMyAdmin la base de datos bd_noticias_fuster con cotejamiento utf8mb4_unicode_ci.

    3. Creación del Usuario de Aplicación (app_noticias):

      • Nombre de usuario: app_noticias
      • Host: localhost
      • Contraseña: AppNoticias2026!
      • Privilegios: Asigna permisos de Datos (SELECT, INSERT, UPDATE, DELETE) y Estructura (CREATE, ALTER, INDEX, DROP) exclusivamente sobre la base de datos bd_noticias_fuster. Sin privilegios globales.

    4. Creación del Usuario de Auditoría (auditor_smx):

      • Nombre de usuario: auditor_smx
      • Host: localhost
      • Contraseña: Auditor2026!Pass
      • Privilegios: Asigna únicamente el privilegio SELECT sobre la base de datos bd_noticias_fuster.

    5. Verificación de Restricciones mediante Consola:

      • Abre la terminal de Linux y conéctate como el usuario auditor_smx: 
        mariadb -u auditor_smx -p bd_noticias_fuster
      • Intenta crear una tabla de prueba ejecutando: 
        CREATE TABLE prueba_fallo (id INT);
      • Comprueba el mensaje de error denegado (ERROR 1142 (42000): CREATE command denied to user 'auditor_smx'@'localhost').
      • Sal de la consola (EXIT;).

    6. Script de Verificación de Privilegios en PHP:

      • Crea el archivo /var/www/html/comprobar_usuarios.php que intente conectar con el usuario app_noticias a la base de datos tienda_fuster: 
        <?php
$conexion = @new mysqli("localhost", "app_noticias", "AppNoticias2026!", "tienda_fuster");

if ($conexion->connect_error) {
    echo "<h1>Acceso bloqueado correctamente</h1>";
    echo "<p>El usuario app_noticias no tiene permisos sobre la base de datos tienda_fuster.</p>";
} else {
    echo "<h1>Fallo de seguridad</h1>";
    $conexion->close();
}
?>
    7. Asigna los permisos adecuados al archivo (chown www-data:www-data y chmod 644).
    8. Abre el navegador en http://localhost/comprobar_usuarios.php y verifica que el acceso resulta bloqueado.

    Comprobación de Privilegios con SQL

    Para ver los permisos exactos asignados a un usuario desde la terminal, puedes ejecutar: 

    SHOW GRANTS FOR 'app_noticias'@'localhost';
